The application: cart, orders and data

Cart and order workflow

The atomic stock reservation (from backend/services/orders.py)

UPDATE product_sizes SET stock = stock - :qty WHERE product_id = :p AND size = :s AND stock >= :qty -- rowcount != 1 => 409 "just sold out", roll back every line

Data model

TableKey columnsWhy
productsslug, name, price NUMERIC(10,2), category, badge, is_activeMoney is decimal, never float
product_sizes(product_id, size) key, stock ≥ 0Stock is per size, which is what is actually bought
orderspublic_id, idempotency_key (unique), totals, address, statusUnguessable reference; replay-safe
order_itemsproduct_name, size, qty, unit_price, line_totalSnapshots: later price or name changes do not rewrite history

Why these choices (and the cost of each)

ChoiceBenefitCost or limit
Cart in a signed cookieNo table; works across two instances with a shared keyPer browser; lost when cookies clear
Idempotency keyDouble click cannot create two ordersNeeds a client-generated key
Liveness vs readiness checksA database blip does not empty the load balancerInstances can be “healthy” yet return 503
Strict CSP, no inline scriptLimits XSS impactAll JS and CSS must be external files
SQLite locally, MySQL on RDSRun and test with no AWS costMySQL behaviour unobserved until the AWS build
