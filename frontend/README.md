# Frontend

The storefront's user interface. It is **server-rendered**: FastAPI renders the Jinja2 templates and serves the static files itself. There is no separate JavaScript application, no Node.js and no build step, by decision (D-017 in [../docs/project/DECISIONS.md](../docs/project/DECISIONS.md)): the smallest stack that still has a real frontend, and one process to deploy.

The backend finds this folder through `FRONTEND_DIR` in [../backend/main.py](../backend/main.py): templates from `frontend/templates`, files under `/static` from `frontend/static`.

## Layout

| Path | Contents |
|---|---|
| `templates/` | 15 Jinja2 templates: `base.html` (header, footer, skip link), `_card.html` (product card), and the pages (home, shop, product, cart, checkout, order, collections, journal, about, policies, architecture, roadmap, error) |
| `static/css/site.css` | Base design system: tokens, typography, layout, responsive rules, reduced-motion support |
| `static/css/modern.css` | Loaded after `site.css`. Current visual theme (white surfaces, red accent, glass panels), the 3D hero and card tilt styles, and the bag, checkout and order styling. It overrides the token values in `site.css` |
| `static/css/engineering.css` | Styles for the `/architecture` and `/roadmap` pages |
| `static/js/boot.js` | Two lines that mark "JavaScript is available" before first paint |
| `static/js/motion.js` | Presentation only: pointer-driven 3D tilt, scroll reveal and the hero entrance. It sets CSS custom properties and never touches prices, stock or the cart. Disabled under reduced motion and on touch screens |
| `static/js/architecture.js`, `static/js/roadmap.js` | Interactive diagram and roadmap tabs. Both pages are fully server-rendered without them |
| `static/js/site.js` | Vanilla JavaScript: mobile menu, quick add, size and quantity controls, bag updates, checkout and newsletter forms. It only calls the backend API; the server is the source of truth for prices and stock |
| `static/images/` | Original SVG illustrations (hero and six products) on a studio-red backdrop, generated by [../scripts/generate_product_art.py](../scripts/generate_product_art.py). Not photographs |
| `static/fonts/` | Cormorant Garamond and Inter (Latin subsets) with their SIL Open Font Licence texts |

## Rules this folder follows

- **No inline script or style.** The Content-Security-Policy allows only same-origin files, and a test fails if a template adds `<script>`, `style=` or `onclick=`.
- **Nothing is loaded from a third party.** Fonts and images are local, so there is no external request and no hotlinking.
- **Works without JavaScript where it can:** navigation, search, filters, sorting and all pages are plain links and GET forms. Cart actions and checkout need JavaScript.
- **Accessibility:** semantic HTML, skip link, labelled controls, visible focus, reduced-motion support. Colour pairs are checked against WCAG AA; screen readers and real devices have not been tested.

## Changing it

1. Edit templates, CSS or JS here; changing a template or the CSS needs no backend change.
2. Run `pytest` and, on a **fresh throwaway database**, `node tools/browser-smoke.mjs http://127.0.0.1:8000 <folder>`; it checks that CSS, fonts and images load, plus flows, keyboard order and mobile overflow.
3. Run `python tools/check_contrast.py` after changing colours.
4. Replacing the illustrations with photographs: [../docs/assets.md](../docs/assets.md).
